# 手順書確認 PoC — レビュー用ブリーフ（7/8 小西さん向け）

- 状態: **ドラフト**（2026-07-07）。動く PoC ＋ 模擬データでの検出実証まで完了。実データ検出は社内環境で実行予定。
- リポジトリ: `office-work/procedure-check-poc/`（ブランチ `feat/procedure-check-poc`）

## 1. これは何か（30秒）

インフラ作業手順書（Excel）に、**今回の特殊手順追加指示が正しく反映されているか**を AI が照合し、
**根拠付きの指摘リスト（Markdown）**を出すツール。最終ジャッジは人間。AI は「見落とすより過検出」で
指摘＋要確認を出し、人間の確認を軽くするのが狙い。

## 2. どう動くか

```
手順書(Excel) ─┐
特殊手順追加指示 ─┼─▶ ①整形(Excel→表) → ②指示と資料を束ねる → ③AI判定 → 指摘リスト.md
過去類似手順(任意)─┘
```

- 1コマンド: `./scripts/run_check.sh 手順書.xlsx 指示.md [過去類似手順.md]`
- 依存は Python + openpyxl のみ。`claude` CLI が無い環境でも、束ねた入力を社内 Claude Code に貼れば同じ判定が出る（可搬）。
- 指摘には**実 Excel の行番号**が付くので、どのセルの話か人間がすぐ追える。

## 3. 何を見るか（14観点）

| 区分 | 観点 |
|------|------|
| A 反映漏れ | 指示作業が無い(A1) / 一部欠落(A2) |
| B 環境誤り | 適用環境が違う(B1) / 対象外環境への手順(B2) / 環境名の転記ミス(B3) |
| C 順序 | 実行順が指示・依存と矛盾(C1) / 前提手順の後置(C2) |
| D 過不足 | 停止・起動漏れ(D2) / 確認手順の欠落(D3) / 切り戻しが変更に未追随(D4) |
| E 転記 | 値の不一致(E1) / パス・資材名の不整合(E2) |
| F 指示違反 | 「実施しない」指示に反する手順の残存(F) |

※「指示に無いだけの手順」は標準手順として**指摘しない**（過検出ノイズを避けるため）。

## 4. 実際の検出例（模擬データ）

正しい手順書にわざと4つ誤りを仕込んだところ、すべて検出・誤検出0（各指摘には実 Excel の行番号が付く）:

| 種別 | 指摘 |
|------|------|
| B1 環境誤り | DB作業が検証機(db-stg-01)向け・本番(db-prd-01)への適用が無い |
| A2 反映漏れ | 対象2台のうち ap-prd-02 の作業が丸ごと欠落 |
| D2 停止漏れ | 変更前の myapp-web 停止手順が無い |
| F 指示違反 | 「実施しない」指示に反し nginx 再起動が残存 |

## 5. テスト（精度の裏づけ）

- **誤り埋め込みテスト**: 14観点それぞれに誤りを仕込み検出できるか＋正しい手順書で誤検出しないかを測定。
- 結果: **14/14 PASS**（`docs/test-results.md`）。正しい手順書（負制御）は**指摘0**。
- 1コマンドで再現可能: `./scripts/run_tests.sh`
- 詳細仕様: `docs/test-spec.md`

## 6. レビューで決めたいこと

1. **環境取り違えの種別の寄せ方** — B1/B2/B3/A2 のどれを主にするか（今は過検出許容で複数出す）
2. **切り戻し手順の扱い** — 指示に明示が無い場合、AI は「要確認」に回す。これで良いか
3. **重大度・合否の基準** — 高/中/低の線引きと、どこまで検出できれば実運用に足るか
4. **過去指摘事例の所在** — 過去レビューの指摘がどこに残っているか（＝実データ再現テストと観点の重み付けの材料）
