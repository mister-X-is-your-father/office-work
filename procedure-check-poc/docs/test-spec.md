## 1. 目的と方針

PoC の判定精度を、次の二段構えで検証する。

1. **誤り埋め込みテスト**（§2）— 指示に完全準拠した「正しい手順書」に、観点ごとの誤りを1つずつ仕込み、
   その誤りを狙って検出できるか（検出率）と、正しい箇所を誤って指摘しないか（誤検出率）を測る。
2. **過去実データ再現テスト**（§3）— 実際の手順書＋開発依頼で、当時の人間レビューの指摘を再現できるか。

評価は「最終ジャッジは人間・見落としより過検出を許容」という PoC の設計方針を踏まえ、
**高重大度観点の検出率を最優先**、誤検出は負制御ケースで管理する。

## 2. 誤り埋め込みテスト

### 2.1 データ設計

- **ベース（正）**: `sample_request.md`（特殊手順追加指示）に完全準拠した手順書を1本用意する。
  - AP: `ap-prd-01` / `ap-prd-02` の各台で 事前確認 → myapp-web 停止 → 設定変更(200→300) → 起動 → 稼働確認
  - DB: `db-prd-01` で バックアップ → パッチ適用 → 適用確認
  - 実施順は AP → DB、nginx 再起動は含めない（除外指示）
- **単一障害ケース**: ベースに誤りを **1つだけ** 仕込む（観点ごとに1ケース）。どの観点が拾えるかを切り分ける。
- **複合ケース**: 実物の乱れを模し、複数の誤りを同時に仕込む（現行 `make_sample.py` がこれ）。
- **負制御ケース**: ベース（誤りゼロ）をそのまま判定 → 指摘0を期待（誤検出率の測定）。

### 2.3 評価指標

- **検出率（recall）** = 期待検出できたケース数 / 全埋め込みケース数。**高重大度観点は 100% を目標**。
- **誤検出率** = 意図しない誤指摘の数。負制御ケース EC-NEG で **0** を目標（「要確認」への計上は誤検出に数えない）。
- **観点カバレッジ** = テスト対象にした観点数 / 全観点数（目標 100%＝A〜F 全て）。
- **箇所精度**（補助）= 指摘の xlsx-row／手順No が実際の誤り箇所と一致しているか。

### 2.4 合否基準（ドラフト・レビューで確定）

- 高重大度観点（A1/A2/B1/B2/C1/C2/D2/E1/F1）の検出率 = 100%
- EC-NEG の誤指摘 = 0
- 中重大度観点（B3/D3/D4/E2）の検出率 ≥ 目安80%（レビューで調整）

### 2.5 実行手順

```bash

python3 testdata/make_sample.py --case B1 -o work/_case_B1.xlsx

```
