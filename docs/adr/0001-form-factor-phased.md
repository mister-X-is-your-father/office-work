# ADR-0001: フォームファクターは「まずGoogle Sheets+Apps Script → 将来Webアプリ」の段階戦略

status: 採用（2026-05-30）
context: office-work プロダクト（会議ファシリOS）の実装形態を決める。

## 決定

Phase 1 を **Google Sheets + Apps Script アドオン**、Phase 2 を **独立Webアプリ（Next.js + Supabase 想定）** とする段階戦略を採る。

## 検討した選択肢

### A. Google Sheets + Apps Script（採用：Phase 1）
- ＋ 既存テンプレ資産(v5)をそのまま製品化。最速で“動く”体験。
- ＋ 配布がコピー1発。ユーザーの学習コストが低い（皆Sheetsを知っている）。
- ＋ 数式・条件付き書式・プルダウンで土台が既に完成。
- − マルチユーザー整合・認証・通知・課金に弱い。Apps Scriptの権限/配布に摩擦。行数で性能劣化。

### B. 独立Webアプリ（採用：Phase 2）
- ＋ UX・自由度・課金・マルチテナントすべて最大。
- ＋ CLAUDE.md のDB規約/skill資産(Supabase等)と相性。
- − 立ち上げが重い。価値検証前に作り込むのは過剰投資。

### C. Notion等の既存プラットフォームのテンプレ
- ＋ 早い。− 自動化・基準内蔵・手法の仕組み化に限界。差別化が出ない。却下。

## 根拠

価値（“規律に頼らず会議で抜け漏れが消える”）はまだ仮説。**最小コストで実体験を作り、検証してから本投資**するのが妥当。Aは既存資産を100%活かして即“閉ループ”を体験でき、学びをBへ移せる。

## 影響

- Phase 1 の自動化は Apps Script（`apps-script/Code.gs`）。行・列の定数は `build_template.py` のテンプレ版に依存（変更時は両方更新）。
- データモデルは Phase 2 のDB設計を見据えて命名（PRD §9）。移行時に Sheets→DB マッピングを行う。

## 再検討トリガ

- 実会議パイロットで継続利用が確認できたら Phase 2 着手。
- Sheets の行数/権限/同時編集が運用の壁になったら前倒し。
