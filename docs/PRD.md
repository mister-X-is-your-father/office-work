# PRD — 仕事のOS（会議ファシリテーション・プロダクト）

status: ドラフト v0.1（2026-05-30 起票）
codename: **OfficeOS**（プロダクト名は未定。候補は §10）
SoT: このファイル。実装・議論はここを更新してから。

---

## 1. 一言で（ビジョン）

> **「会議をするだけで、ファシリが上達し、タスクと論点が勝手に溜まり、抜け漏れが構造的に消える——“仕事のオペレーティングシステム”」**

『世界で一番やさしい会議の教科書』(榊巻亮/日経BP) の手法を“仕組み”に埋め込み、**人の規律・記憶に頼らずに**良い会議とやり切りを実現する。

## 2. 解く課題（Problem）

1. **会議がグダグダ**：終了条件・決定・ToDoが曖昧。ファシリのスキルが属人的。
2. **取りこぼし**：決まったのに記録されない／記録したのに追われず放置（＝前からの放置）。
3. **盲点**：そもそも誰も挙げていない“やるべき/議論すべきこと”に気づけない。
4. 既存ツール（Notion/タスク管理）は**箱はあるが、(a)会議の質を上げる導線がない (b)人が真面目に入力する前提**。

## 3. ターゲット

- 会議に疲れた現場リーダー／中小チームのマネージャ
- 抜け漏れに悩む PM・進行役
- ファシリに自信のない若手（“隠れファシリ”から始めたい層）

初期フォーカス: **継続プロジェクトを回す5〜15人規模のチーム**。

## 4. 独自性（Wedge）

- **操作そのものが入力になる**：スクライブ（意見/論点/決定）で会議を進めると、それが構造化データとして溜まる。別途“議事録を書く”が消える。
- **網羅の基準を内蔵**：「必ず扱う領域マップ」を標準装備し、現実と突き合わせて盲点を炙り出す。
- **手法が仕組み化**：終了条件・確認・発散収束・カバレッジが、画面の導線として強制される＝規律に頼らない。

## 5. コアループ（プロダクトの本体）

```
🧭 基準(網羅チェック)＋🗂台帳の残から「今日の論点」を引く
   ↓
▶ 会議：スクライブで「意見/論点/決定」が型化（＝自然にファシリ）
   ↓  ※操作＝入力。別途記録しない
🗂 台帳へ自動集約（決定・ToDo・論点）
   ↓
📊 棚卸し：前からの放置・停滞・盲点が勝手に浮く
   ↓
次の会議の準備へ（持ち越し自動セット）
```

このループを**人手ゼロ**で回すのが到達点。

## 6. 抜け漏れの2レイヤー（設計の肝）

| 種類 | 内容 | 守る仕組み |
|---|---|---|
| 会議内 | その会議で扱うべき論点の網羅 | 論点リスト先出し＋カバレッジ＋MECE観点チェック |
| 仕事全体①取りこぼし | 書いたのに落ちる/放置 | 🗂台帳（唯一の箱）＋棚卸し（期限超過/停滞/担当なし自動） |
| 仕事全体②盲点 | そもそも挙がってない | 🧭網羅チェック（基準）と現実の突合（未着手の必須/久しく未議論） |

## 7. フォームファクター戦略（段階）

- **Phase 1（今）= Google Sheets + Apps Script アドオン**。既存テンプレ資産をそのまま製品化。最速で“動く”。配布はコピー1発。
- **Phase 2（将来）= 独立Webアプリ（Next.js + Supabase 想定）**。手応えが出たら移行。マルチユーザー/通知/分析/AI支援。
- 判断根拠は ADR-0001 参照。

## 8. スコープ

### Phase 1 / MVP（＝次に作る）
- 4タブ Sheets テンプレ（▶会議 / 🗂台帳 / 🧭網羅チェック / 📖ガイド）※v5で土台完成
- **Apps Script 自動化（閉ループ化）**:
  1. **「新しい会議」メニュー** … ▶会議を複製し日付命名、前回の未完サマリを冒頭に自動セット
  2. **会議→台帳 自動転記** … ▶会議③の「決定/ToDo」を🗂台帳へ追記（重複防止）
  3. **最終更新の自動打刻** … 台帳の行を編集したら `最終更新日` を自動更新（→「停滞」が本当に自動で浮く）
  4. **カスタムメニュー**「会議OS」… 上記アクションをワンクリックで
- 数式（カバレッジ・予実・コスト・点数）と条件付き書式・プルダウンは既存を踏襲
- 保護：数式セルの誤上書き防止（シート保護）

### Phase 1 で“やらない”（Out of Scope）
- マルチユーザー同時編集の整合、認証、外部通知、ポートフォリオ横断、モバイル最適化、課金 → Phase 2

## 9. データモデル（概念）

Sheets では各タブが下記エンティティに対応。Phase 2 の DB 設計の素地でもある。

- **meeting**（会議）: title, datetime, facilitator, scribe, purpose(終了条件), type, planned_min, actual_min, achievement, status
- **agenda_item**: meeting_id, topic, goal, planned_min, actual_min, order
- **scribe_entry**: meeting_id, time, kind(意見/論点/決定), content, speaker
- **issue**（台帳の1行＝課題/タスク/論点/リスク/依存/決定を統合）: area_id, kind, title, status, owner, due_date, priority, source_meeting_id, last_update, next_action, resolution
- **area**（網羅チェックの1行）: name, description, required, status, last_discussed_at, owner, note
- **project** / **user**（Phase 2 で導入）

> Phase 2 DB 規約（CLAUDE.md準拠）: UUID v7、snake_case、全table `created_at/updated_at/deleted_at`(timestamptz, soft delete)、enum は CHECK制約、`tenant_id` を user-facing table に、index は `(tenant_id, …)` 基本。詳細は別途 data-model.md（Phase 2 着手時）。

## 11. 成功指標（KPI 案）

- ファシリ点数（8基本動作）平均の上昇
- 🗂台帳の「停滞」「期限超過」件数の減少
- 🧭未着手の必須領域 件数の減少
- 会議時間 予実差の縮小
- 週次の継続利用率（リテンション）

## 12. リスクと対応

| リスク | 対応 |
|---|---|
| 規律依存（入力されないと台帳が嘘をつく） | Apps Scriptで自動転記/自動打刻＝人手依存を構造で除去 |
| Apps Script の権限・配布摩擦 | 導入手順を整備、将来はアドオン公開 or Web移行 |
| Sheets の性能（行数増） | アーカイブ運用、Phase 2 でDB化 |
| 入力負荷 | 「操作＝入力」設計でそもそも別作業を作らない |

## 13. オープンな論点（Open Questions）

- プロダクト名の確定
- 初期ターゲットの絞り（プロジェクト型 vs 定常業務型）
- 配布形態（テンプレ共有 / Workspaceアドオン審査）
- Phase 2 の課金モデル（後回し）

## 14. ロードマップ

- **P0（完了）**: Sheetsテンプレ v5（数式/ドロップダウン/条件付き書式/カバレッジ）
- **P1（次）**: Apps Script 閉ループ自動化（§8 MVP）＝“人手ゼロ”の体験
- **P2**: 仕上げ＋実会議パイロット（導入手順・保護・名前）
- **P3**: Webアプリ化（Next + Supabase）、マルチユーザー、通知、AI支援（議題から論点を提案／自動要約）
