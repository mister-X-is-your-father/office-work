## 3. ★カンバン：現状と理想の差異 ＜✅実装完了 2026-06-18＞

> **完了**: 下記「推奨実装方針」どおり再設計を実装。bucket依存を撤廃しフロント自前グルーピング（ステータス軸）
> ＋プリセットタブ＋案件スイムレーン＋期限ヒート/停滞/WIP警告カード＋DnDでステータス変更（moveStatusに集約・
> history.jsでUndo/Redo）＋列内＋追加。ブラウザ目視（通常/案件レーン）・DnD→Undo往復・consoleエラー0を検証済み。
> 未対応で残った論点: 軸の動的切替（担当/重要度/分類軸。現状はステータス軸＋案件レーンのみ）、列の並べ替え/WIPカスタム、
> 概要(summary)の「WS別配分」の扱い（下記）。以下は実装時点の設計メモ（記録として残す）。

### 現状（旧。`app/views/kanban.js`、API `lib/api.js:44-48`）
- 起動: `projects` からWS一覧→ `ts.kanban.ws` で**単一WSを選択**。WS無し/kanbanビュー無しは「ありません」表示で停止。
- 列 = **Vikunjaのbucket（kanbanビュー固有）**。getViewTasks(pid,vid)で bucket[]+tasks[]。列の追加/改名/削除はあるが**並べ替え/WIP/色なし**。
- カード移動 = `moveTaskToBucket`＝**bucket上書き（ステータス変更ではない）**。
- **スコープ=単一WSのみ・全タスク横断不可・絞り込みなし・列内カード追加なし**。
- WS非表示方針と不整合（WS選択UIが残る・Inbox運用だと窮屈）。

### 理想（ユーザー「超思い通りになる柔軟なカンバン」）と差異
1. **任意軸グルーピング**（ステータス/担当/重要度/プロジェクト=親タスク/分類）←→ 今はbucket固定 🔴
2. **全タスク横断**（WS非依存）←→ 今は単一WS 🔴
3. **ステータス軸カンバン**（未着手/進行中/連絡待ち/完了の自動列、移動でstatus変更）←→ 今はbucket軸 🔴
4. グルーピング軸の**動的切替タブ** 🟡
5. 列の**並べ替え/WIP/色/非表示** 🟡
6. **絞り込み**（プリセットタブ連携：未整理/今日/期限切れ等） 🟡
7. **列内「＋」でカード追加** 🟠

### 推奨実装方針
**Vikunja bucket依存をやめ、フロントで自前グルーピング・カンバンを描画**するのが柔軟で筋が良い：
- `load()` の全タスクを `statusOf(t)` / `humanAssignees(t)[0]` / 重要度 / 親タスク(parentOf) / 分類ラベル で**フロント側グルーピング**。
- 軸切替タブ（status/担当/重要度/プロジェクト/分類）＋選択を localStorage 永続。
- DnDで列移動→その軸のフィールドを更新（status軸ならstatus、担当軸ならassignee付け替え 等）。**Undo/Redo(history.js)に積む**と一貫。
- プリセットタブ（taskMatches）で絞り込み、列内「＋」でインライン追加（taskform/quickaddのensureInbox流用）。
- 既存のVikunja-bucketカンバンは「ステータス軸の一形態」として温存 or 廃止は要相談。
- DnDは gantt/table の作法（HTML5 draggable）を流用。WS非表示方針とも整合（WS選択UI不要に）。
- 工数: 中（レイアウト/DnDは既存流用可。フォーク改修は基本不要＝フロントのみ）。

### 概要(summary)の「WS別配分」も要相談
WS非表示にしたのでWS別配分セクションは浮く。残す/プロジェクト(親タスク)別配分に変える/削除、を要確認。

## 3.5 ★メニュー表示/非表示の管理者制御＋各人別出し分け ＜✅実装完了 2026-06-18＞

> **完了**: ROUTES/ORDER を `app/lib/routes.js` に抽出し app.js/settings.js で共有。チーム設定(管理者のみ)に
> 「メニュー表示」セクション＝メンバー選択→ルートON/OFFのマトリクスを追加。保存先は exec の team settings
> `menu_visibility: {"<userId>": ["hiddenRouteKey",...]}`（ブロックリスト＝未登録は全表示・home は必須で常時表示）。
> app.js の applyMenuVisibility() が本人のナビから非表示ルートを除去＋空グループ見出しも片付け、route() で隠しルート
> 直URLはホームへフォールバック。exec.py の POST /settings に menu_visibility のサニタイズ＋保存を追加（repo版に
> 欠けていた sort_presets も同時に追補＝repo↔デプロイのドリフト解消）。ブラウザ実機で保存→リロード→ナビ除去→
> 直URLガード→復元まで検証済み・consoleエラー0。設計メモは以下に残す。

ユーザー要望(2026-06-17): **左ナビ各メニューの表示/非表示を、管理者権限を持つ人が設定できるように。さらにそれを各人別に出し分け**（誰にどのメニューを見せるかを管理者が決める）。

### 要件
- **管理者のみ設定可**（`settings.canEdit` が管理者フラグ。チーム設定保存と同じゲート）。
- **ユーザーごとに表示メニューを設定**（例: 森田=全部 / tanaka=ホーム・タスク一覧・報告のみ）。管理者がメンバー×メニューのマトリクスでON/OFF。
- 設定は**チーム共有＝サーバ保存**。各人がログインすると自分の可視メニューだけナビに出る。

### 実装方針
- **保存先**: exec service の team settings JSON に `menu_visibility: { "<userId>": ["hiddenRouteKey", ...] }` を追加。`lib/store.js` が settings に載せて返す（祝日/容量等と同じ経路）。
- **ナビ描画**: `app/app.js` の shell()/ORDER 走査で、`whoami().id` の非表示集合を除外してナビ生成。隠れたルートへ直URLで来た時はホームへフォールバック。ホーム等の必須メニューは常時表示で固定してよい。
- **設定UI**: チーム設定(settings-team・管理者のみ表示)に「メニュー表示」セクション＝メンバー選択→各ルート(ROUTES.label)のON/OFF。隠し系(fable)や設定自体の扱いに注意。
- 左サイドバー折りたたみ等の**ローカルUI状態とは別物**（こちらはサーバ・全体・管理者制御）。
