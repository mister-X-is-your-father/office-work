# AI×人間 協業プロトコル（TaskStation）

**status: 運用中（2026-07-03〜）** ／ SoT: このファイル。MCPサーバ = `ops/taskstation-mcp.py`（デプロイ先 `~/.local/bin/taskstation-mcp.py`）

人間（森田・id7）と AI（fable・id8、実体は Claude Code セッション）が TaskStation を共有ボードとして協業するための規約。TaskStation 側に特別な画面は不要 —— 既存の分類ラベル・コメント・ステータス・進捗率だけで回す。

## 1. タスクの分類（誰がやるか）

分類ラベルで宣言する（タスク作成時 or 後から付け替え）:

| ラベル | 意味 | AIの振る舞い |
|---|---|---|
| **AI** | AIが自走して完了まで持っていく | my_agenda に載る。着手→進捗→完了まで自律。判断が必要なら escalate |
| **人間** | 人間専用 | AIは読み取り以外触らない |
| **AI+人間** | AIが下準備し、人間へ申し送り | AIは自分のパートを終えたら post_comment で申し送り＋進捗%を実態に合わせ、担当を人間に寄せる |

補助として担当者も併用可（AI タスクに fable を assign すると「自分の担当」フィルタが人間タスクだけになる）。

## 2. AI の作業ループ（Claude Code セッションの作法）

```
my_agenda                    … 今やるべきタスクを確認（期限順・人間待ちは分離表示）
  ↓ タスクを選ぶ
start_task(plan=作業計画)     … 着手宣言。計画がコメントに残る（進行中に遷移）
  ↓ 実作業
set_progress + post_comment  … 節目ごとに進捗%と作業ログを記録
  ↓ 分岐
├─ 詰まった → escalate(reason, options)   … 連絡待ちに遷移＝人間の一覧に浮き上がる
│     ↓ 人間がコメントで回答
│   resume_task(note)                      … 連絡待ち解除→進行中に復帰
└─ 完了 → complete_task(summary)           … 完了報告（何をした/成果物の場所/検証状態）必須
```

### コメント規約（全員閲覧・タスク編集モーダルのコメント欄）

- `🤖 ▶ 着手します` … start_task の計画
- `🤖 …` … 進捗・作業ログ（post_comment）
- `🚨 エスカレーション（人間の判断が必要です）` … ■状況 / ■提案・選択肢 の2部構成。**選択肢を必ず添える**（人間が Yes/No か番号で返せる形）
- `🤖 ✅ 完了報告` … 何をした・成果物の場所（パス/URL/コミット）・検証状態

`add_note`（AIノート）は下書き・思考メモ用（作成者のみ閲覧）。人間に見せる情報は必ず post_comment。

### MCPが強制する運用ルール（2026-07-03〜・お願いではなくツールがエラーで拒否する）

セッションごとに使い方がばらつかないよう、以下は MCP ツール自体が強制する:

| ルール | 強制のされ方 |
|---|---|
| ステータスは4値（未着手→進行中→連絡待ち→完了）・遷移はツール経由のみ | 着手=start_task / 人間待ち=escalate / 再開=resume_task / 完了=complete_task |
| 完了時は完了報告が必須 | complete_task の summary が必須引数（何をした・成果物の場所・検証状態） |
| 「進捗100%なのに未完了」を作らない | set_progress(100) はエラー→ complete_task へ誘導 |
| resume_task は連絡待ち解除専用 | 連絡待ちでないタスクにはエラー→ start_task へ誘導 |
| 分類「人間」のタスクはAIから変更不可 | 変更系8ツール（start/progress/estimate/due/complete/escalate/resume/schedule）が拒否。コメント・依存付けは可 |
| 完了済みタスクの再開はAIからしない | start_task が拒否（戻すのは人間がUIで） |
| 期日の無断変更禁止 | set_due のみ・reason 必須・変更はコメント＋履歴に記録 |

## 3. 人間側の見え方（TaskStation で完結）

- **進捗**: 一覧・かんばん・ホームの進捗%とステータスがそのまま AI の実施状況
- **エスカレーション**: ステータス「連絡待ち」で浮き上がる（一覧の連絡待ちタブ／かんばん列）。タスクを開いてコメントの選択肢に返信 → AI が次のセッションで resume
- **履歴**: タスクのコメント欄が時系列の協業ログになる

## 4. 週末スプリント運用（例: 金土日 3h×3）

1. タスク投入時に見積り(h)と期限（金/土/日）を設定し、分類ラベルを付ける
2. `schedule_task(task_id, date, hours)` で日別予定を載せる → 週プランナー/ガント/稼働プランに表示され、1日の負荷が見える
3. 1日の合計見積りを枠（3h）以内に収める。超えたらタスクを翌日に送るか分割（create_task で分割可）
4. セッション開始時の合言葉は「今日のAIタスクを進めて」だけでよい（instructions が作法を知っている）

注意: キャパ計算は土日を稼働0時間として扱うため、土日に予定を載せるとキャパ警告が出ることがある（実害なし・仕様）。

## 5. 接続情報

- MCP 登録（ユーザースコープ済み）: `claude mcp list` に `taskstation` が出る
- 認証: `~/.config/taskstation/fable.env`（fable アカウント）— コメント・変更は fable 名義になり、人間の操作と区別できる
- fable-runner（15分毎の自動提案タイマー）は同じ MCP の既存6ツールを使用。v2 でも後方互換維持
