# 実行サポート フェーズ2 要件定義: 実行ループ＋キャパ保護

> status: **設計中** ／ 2026-06-20 起票 ／ 前提: フェーズ1（着手準備パネル＝準備の仕組み）は完了
> SoT(フェーズ1): `docs/exec-support-spec.md`

## 0. なぜやるか（現状の正直な評価）
フェーズ1で「実行可能性を上げる準備」は強力にできた（曖昧さ/摩擦/忘却を機械的に削る）。
だが **メーター100%＝“準備完了”であって“実行された”を保証していない**。「計画を絶対に実現する」には:
- **実行を閉じるループ**（やったか追跡→ずれたら督促/再計画→人の目）
- **キャパ保護**（再計画しても詰め込んだら破綻するので、容量を超えさせない）
体感: 準備70 / 実行20 / 運用10 → このフェーズで実行・運用を引き上げる。

---

## A. 実行ループ（準備→“やらざるを得なくする”へ）
```
逆算で日付の入った手順 → 「今日やる1手」に自動抽出（朝のMIT）
        ↓ 着手日/トリガー時刻に 通知が鳴る（notify連携）
   「今すぐ着手」→ ステータス進行中＋ポモ開始
        ↓ その日が終わって未実行なら → 検知して督促＋自動再逆算
        ↓ 進捗を報告/ステータスに反映（人の目＝アカウンタビリティ）
```
- **E1 今日の手順 自動抽出**: prep の段取り(steps)で `due==today` の手順を「今日やること」に集約（ホーム/稼働予定/専用）。MIT＝今日の最重要1〜3。
- **E2 着手日・トリガー通知**: 手順の着手日が来たら、また if-then の時刻/条件で notify を発火（既存 notify.js に乗せる）。
- **E3 今すぐ着手**: パネル/今日ビューのボタン → タスクを「進行中」に＋ポモドーロ開始（pomodoro.js 連携）。
- **E4 未実行検知＋再逆算**: 着手日を過ぎて未完了の手順を検知し、督促表示＋残り手順を**自動で再逆算**（締切から再配置）。再逆算で間に合わないなら A→B のオーバーコミット警告へ。
- **E5 報告・アカウンタビリティ**: 進捗/未実行を報告ビュー・ステータスに反映（上司対策と接続。“昼の攻撃”を逆手に取り、午前に「今日やる1手＋準備済み」を提示）。

## B. キャパ保護（食いつぶされない仕組み）
1. **F1 全タスク横断の capacity-aware 逆算**: 逆算は「その日に既に入っている他タスクの予定(plans)＋保護枠＋バッファを引いた**実空き**」にしか置かない（現状は1タスク視点）。
2. **F2 バッファ強制確保**: 毎日 capH の X%（既定20%）or 固定枠を割り込み用に予約し、スケジューラは埋めない（保護時間帯の毎日版・team設定 `daily_buffer_pct`）。
3. **F3 オーバーコミット早期警告**: 逆算が締切までにキャパ内で全手順を置けないと判明した瞬間に赤信号＋選択肢（締切交渉/縮小/委譲/優先入替）。
4. **F4 キャパ予算（時間家計簿）**: 週/日の残容量を可視化（残高）。残0近づくと新規コミットを警告/ゲート。
5. **F5 割り込み＝ゼロサム**: 満杯の日に新規/割り込みが来たら「何かを外すか別日へ」と迫る（黙って詰め込ませない）。
6. **F6 ディープワーク枠**: 最重要タスク専用の確保枠（保護枠の逆）。会議/割り込みが奪えない時間。

## C. 既存資産との接続
- 容量: `settings.capH`、`lib/capacity.js`（loadByMember 等）、祝日 `holidaysSet`、休暇 `unavailabilityByMember`。
- 予定: タスクの `time_planned` / 日別 plans（logPlan・時刻カレンダー）。
- 保護: 既存 `protected_windows`（曜日×時刻帯）＋本フェーズで `daily_buffer_pct` を追加。
- 通知: `lib/notify.js`（個人設定でON時に発火）。
- 準備: exec `/prep`（steps[].due, score）。バッチ `/prep` でホーム集約済み。
- 着手: `pomodoro.js`、`updateTask`（status=進行中）。

## D. スコープ（小波に分割）
- **波E（実行ループ）**: E1 今日の手順抽出 → E2 通知 → E3 今すぐ着手 → E4 未実行検知＋再逆算 → E5 報告連携。
- **波F（キャパ保護）**: F1 横断逆算 → F3 オーバーコミット警告 → F2 バッファ → F4 予算 → F5 ゼロサム → F6 ディープワーク枠。
- **推奨初手**: **E1（今日の手順）＋ F1（横断逆算）＋ F3（オーバーコミット警告）**。
  - E1 で「今日やる1手」が現れ、F1+F3 で「そもそも入り切るのか」を計画時に突きつける＝“実現”に最も効く。
  - 次に E2 通知 / E3 今すぐ着手 / E4 再逆算 と続ける。

## E. 受け入れ基準（波ごと）
- E1: prep の段取りで today 着手の手順が、ホーム/今日に「今日やる1手」として出る。
- F1: 逆算が他タスクの当日負荷＋保護枠＋バッファを引いた実空きにのみ配置する。
- F3: 締切までに置き切れないと、計画時点で赤警告＋具体的選択肢が出る。
- 共通: ブラウザ目視・consoleエラー0・指示1=1コミット・views はサブエージェント委譲（マーカー方式）。

## F. 未決事項

- 「今日やる1手」の置き場所（ホームの専用カード / 稼働予定(today.js) / 新ビュー）。today.js は別作業の対象になりうるので要調整。
- 再逆算の発火タイミング（パネル表示時 / 日次 / 手動）。
- アカウンタビリティ（上司対策C＝Slack）は要 bot/webhook（別途）。

## G. 実装方針（運用契約準拠）
- 共有: `ops/taskstation-exec.py`（buffer設定・必要なら集約API）・`lib/*`・通知・`taskform.js` は指示役が中央編集。
- 画面: `exec-support.js`（逆算/警告/今日の手順）・ホーム/今日の表示は views = サブエージェント委譲（**マーカー `/tmp/cap-view-edit-allow` で委譲ウィンドウを開閉**）。
- 検証: ブラウザ目視（セッション切れ時は fable サービスアカウントでトークン注入・**読み取り中心/可逆操作のみ**）。
