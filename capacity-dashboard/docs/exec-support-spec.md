# 実行サポート フレームワーク 要件定義 v0.1

> status: **設計中（要件確定フェーズ）** ／ 2026-06-19 起票
> 目的: 「重要タスクを“遂行”するための機能」を、手法を差し替え・追加できる**フレームワーク**として作る。

## 1. 背景・課題
実ユーザー森田の本丸ボトルネック＝**設計済み未実行**（計画はできるが着手・実行に踏み込めない）。
既存機能は「選ぶ・カンバン・ポモドーロ・週計画・習慣」が揃うが、**「計画→着手」の橋渡し**が薄い。
ここに、着手の不確実性を機械的に削る「実行サポート」を据える。

## 2. コンセプト
タスクに付ける**「着手準備パネル（実行リハーサル）」を中心**に、複数の実行手法を**プラグイン**として載せる。
埋まり具合を**実行可能性メーター**で可視化し、「もう実行されるしかない状態」への到達度を手応えにする。

## 3. フレームワーク設計（メソッド・レジストリ）
各手法は自己記述プラグイン。コアを触らず追加・ON/OFF・並べ替えできる。
```
plugin = {
  id, label, icon,
  fields   : 入力スキーマ（何を埋めるか）
  score    : 完成度 → 実行可能性メーターへの加点
  symptoms : 診断タグ（先延ばし / 曖昧 / 準備不足 / 集中できない …）
  onApply  : 既存機能への反映（plan/期日/通知/subtask 等）
}
```
- **着手準備パネル**: 有効プラグインを汎用描画。
- **実行可能性メーター**: 各プラグインの score 合計を正規化（満タン＝実行されるしかない）。
- **診断「何が止めてる?」**: symptom → 該当プラグインへ誘導。
- **設定**: プラグインの ON/OFF・並び（個人 / チーム）。

## 4. 組み込みプラグイン（v1）
| id | 手法 | fields | symptoms |
|---|---|---|---|
| next_step | 次の一歩（最小着手） | 2分で始まる物理動作1つ | 曖昧/着手の壁 |
| steps | 段取り（手順化） | 順序付き手順（各：見積/期日/担当） | 大きすぎ/曖昧 |
| schedule | 予定化・スケジュール | 手順/タスクをカレンダー枠・期日へ（逆算/前進・容量考慮） | 計画が予定に落ちてない |
| if_then | if-then トリガー | いつ・どこで・何をきっかけに | 先延ばし |
| prereqs | 必要なもの | 物/情報/承認のチェックリスト | 準備不足 |
| obstacles | 想定する壁＋対策 | 障害 → if-then 対策（WOOP） | 不安/挫折予感 |
| dod | 完了の定義 | 「終わった」と言える状態 | ゴール不明確 |

## 5. 実行可能性メーター（加点例）
next_step=20 / when-where(if_then)=15 / prereqs全✓=15 / steps=15 / schedule済=15 / obstacles=10 / dod=10 → 100。
**この数値が機能の主役**（埋めるほど着手不確実性が下がる）。

## 6. データ保存（決定済み）
taskstation-exec に **`/prep/:taskId`（GET/POST）** を新設。既存 `/notes/:taskId`（AIノート）と同作法。
本体は `{ [methodId]: data, score }` の汎用JSON。段取りは軽量JSONで持ち、予定化時のみ既存 plan(logPlan)/期日へ反映。

## 7. 既存機能連携
段取り→subtask/plan、予定化→時刻カレンダー(logPlan)・期日・容量(capacity)・祝日/休暇、見積→time_estimate、
壁/トリガー→通知(notify)、進捗→percent_done ロールアップ、依存→depgraph/follows。

## 8. スコープ
- **v1（MVP）**: レジストリ基盤＋着手準備パネル（組み込みプラグイン）＋実行可能性メーター＋exec `/prep` 保存＋設定ON/OFF＋タスクからの起動。
- **後続**: 診断サジェスト、逆算スケジュールの自動配置、段取りテンプレ、「止まってる重要タスク」一覧からの一括リハーサル、プラグインの並べ替えUI。

## 9. 受け入れ基準
タスクを開く→項目を埋める→メーターが上がる→exec に保存→再表示で復元→「今すぐ着手 / カレンダーに予約」が押せる。
設定で手法をON/OFFできる。consoleエラー0・ブラウザ目視。

## 11. 実装方針（運用契約準拠）

- 画面: 新規 `views/exec-support.js`（or taskform タブ）はサブエージェントに委譲。
- 検証: ブラウザ目視＋consoleエラー0＋node --check、指示1=1コミット。
