# 設計思想

> status: ドラフト（要件 v0.1）。モック段階の判断を記録したもの。実データ接続前。

## 1. 何を解きたいか

少人数チーム（2〜4名）の運用で、市販OSSのPM/タスクツールが**苦手にしている一点**を埋めたい:

> **「今日、メンバー一人ひとりにどれだけ空きがあるか／誰に新しい仕事を振れるか」を一目で。**

これは Instagantt（商用SaaS）の **Workload ビュー** が一番近い（誰が過負荷で、どこに空き容量があり、各人の見積り時間がアサインにどう効くか）。だが Instagantt は **クローズドSaaS・セルフホスト不可** で、データ主権・OSS要件に合わない。

→ **狙い: Instagantt の Workload 相当を OSS・自前ホストで。**

## 2. なぜ自前で作るのか（車輪の再発明ではない）

- ガント・カンバン・タスク管理・権限などの**汎用PM機能は OSS がタダでくれる**。ここは自作しない。
- しかし**「人別・日別キャパの自動可視化」だけはどのOSSも持っていない**（評価した5ツール全てで弱点だった）。
- よって自作するのは「不在機能の補完」であって、再発明ではない。原則（使えるライブラリは必ず使う／abstraction越し）に沿う。

## 3. 要件 v0.1

| 項目 | 決定 | 理由 |
|---|---|---|
| 主目的 | **空き容量さがし**（今日、誰に振れるか） | チームの一番の困りごと。発注/受注の即断に効く |
| 時間軸 | **今日（日次）中心** | まず日次の運用。週/月/スプリントは補助ビューへ |
| 工数の出どころ | タスクの**見積り時間**（`est:4h` ラベル等） | TaskStation に見積り時間フィールドが無いため。[ADR-003](01-decisions.md) |
| キャパ | まず**全員一律 8h/日** | シンプルに開始。人別稼働率・休暇は将来拡張 |
| データ源 | **TaskStation API**（＋一部 Claude 要約） | [ADR-001](01-decisions.md) / [ADR-002](01-decisions.md) |

## 4. 5つの切り口（機能の地図）

キャパ系ツールが答える問いは5つに整理できる。モック群もこれで分類している。

| # | 切り口（答える問い） | 時間軸 | 代表画面 |
|---|---|---|---|
| ① | **今、誰に振れる？**（運用・空きさがし） | 今日 | 空き探し各種・アサイン |
| ② | **この先、回る？溢れる？**（計画・負荷ならし） | 週/スプリント | 週プランニング・着地見込み・What-if |
| ③ | **誰が危ない？**（リスク・健全性） | 週・連続 | 過負荷ヒストリー（燃え尽き検知） |
| ④ | **何にリソースを使ってる？**（配分） | 任意 | プロジェクト別配分・ポートフォリオ |
| ⑤ | **見積り合ってた？**（実績・精度） | 振り返り | 見積り vs 実績 |

これに加えて、運用の入口になる **総合ビュー**、横断の **ガント**、日々の **タスク管理（かんばん/一覧/カレンダー等）**、**構造化・優先度（WBS/MoSCoW/RICE）**、**深掘り・検索・AI Q&A** を用意。
全画面の一覧は [02-screens.md](02-screens.md)。

主目的は①なので、**重心は常に「今日の空き」**。他は周辺として配置する。

## 5. アーキテクチャ（構想）

```
┌─────────────────────────────┐        ┌──────────────────────────────┐
│ TaskStation（タスクの箱・OSS）   │        │ 自前 Capacity レイヤー        │
│ - タスク / 担当 / 期日       │  REST  │ - キャパ計算（空き/超過/着地）│
│ - ラベル（est:4h で工数）    │◀──API──│ - 可視化UI（本リポジトリ）    │
│ - サブタスク / 優先度        │        │ - Claude で自然文要約(任意)   │
└─────────────────────────────┘        └──────────────────────────────┘
        ↑ 本体は fork しない（API越し）            ↓
        └── アップグレード追従を殺さない    Next.js + Supabase/Postgres（想定）
```

- **TaskStation 本体は改造しない**。すべて **REST API 越し**にデータを読む。[ADR-002](01-decisions.md)
- 見積り時間は TaskStation の**ラベル**（`est:4h`）やタイトル末 `[4h]` をパースして得る。[ADR-003](01-decisions.md)
- キャパ計算（容量−アサイン＝空き、超過、着地予測）は**自前レイヤーの責務**。
- 自然文Q&A（「今週ヤバいのは？」）は **Claude** で要約（画面 53）。

## 6. やらないこと（スコープ外・v0.1時点）

- TaskStation 本体のフォーク／UI改造
- 人別稼働率・休暇・祝日・勤務時間帯（将来拡張。設定画面 17 に余地）
- 双方向編集（アサイン変更の書き戻し）は段階2以降。まず読み取り専用。
- 認証/マルチテナント等の本番非機能要件（プロト段階では後回し）
